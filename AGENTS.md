# Stremio Catalog MCP agent instructions

- This repository is a catalog-only MCP server and Stremio addon, **not a CLI**. Keep the Go API and ZueDocs deployment on Vercel, not Cloudflare Workers.
- Use the official Go MCP SDK and **stateless Streamable HTTP** so Vercel functions don't require persistent sessions.
- The only Go Function entrypoint is `api/mcp.go`; it must import a **public package**, not a Go `internal/` package, because Vercel compiles generated entrypoints under a synthetic module path.
- Authentication is via one `?key=` parameter matching the `MCP_API_KEY` environment variable. Missing configuration fails closed. Never log full authenticated URLs.
- `pkg/server/tools.go` exposes catalog, Home layout, and watch-history tools; do not add a recommendation engine, tasting/ratings database, streaming sources, or duplicate metadata provider.
- **MCP tool annotation rule:** Always advertise every tool with `annotations.readOnlyHint: true` and omit `annotations.openWorldHint` entirely. Use the shared `catalogTool` helper, including for new tools. Add/update a `tools/list` contract test whenever changing the tool surface. The hints are discovery metadata only; they do not change write behavior or API-key authorization.
- `pkg/catalog` owns durable state in dedicated Upstash Redis via HTTPS; use optimistic compare-and-swap for all edits. Never reuse another application's Redis database.
- By default, expose exactly five MCP tools: `catalogs_get`, `catalogs_update`, `home_layout_get`, `home_layout_update`, `watch_history`. Catalogs manage content; Home layout manages row and addon presentation; watch history inspects and explicitly marks movie/episode completion in the Stremio account. Preserve poster URLs in detailed catalog read and update responses. `catalogs_update` batches and validates modifications before one Redis CAS; `request_id` guards retrying creates. Do not expose deprecated one-off catalog tools.
- Optional TMDB title lookup: expose `title_lookup` only when `TMDB_READ_ACCESS_TOKEN` or `TMDB_API_KEY` is configured. Search 1–50 names with bounded concurrency and 429 handling; return IMDb IDs, title, year, language, genre, and best-effort IMDb ratings via Cinemeta. Return up to six ranked, verified IMDb matches for conflicting titles; process more candidates before truncation, and never silently guess when a retrieval fails. Accept year and adaptation qualifiers and normalize punctuation/diacritics and transliterations, without edit-distance typo correction. Do not expose credentials in errors or confuse TMDB votes with IMDb ratings.
- `pkg/stremio` provides catalog endpoints, the account-sync adapter, and explicitly requested Home layout changes. Normal `catalogs_update` synchronization must preserve **all fields** of unrelated addon descriptors. `home_layout_update` may change only the explicitly selected catalog visibility/order or installed addon order; never uninstall Cinemeta or streaming providers. Preserve unrelated manifest fields, flags, URLs, and stream resources.
- `watch_history` accepts **only IMDb IDs** for get/check/mark_watched/mark_unwatched, never title queries or years. `get` lists recent history or inspects one ID; `check` accepts 1–50 distinct `imdb_ids` and must query exactly those IDs with a single datastoreGet, preserve input order, avoid state changes, and return `watched`/`partially_watched`/`not_watched`/`unverified`. **A fully watched series must return the same minimal `check` shape as a fully watched movie: no seasons, episode lists, counts, or spoiler boundary.** Partially watched series return *only exact watched episode numbers* grouped by season, not episode names or plots. Do not claim an absent record proves the user never watched the title; do not mark corrupt/missing bitfields as unwatched. Episode ordering uses full canonical Cinemeta metadata; only recorded series need Cinemeta metadata, queried with bounded concurrency. Whole-title `mark_watched` (no season/episodes) MUST mark all known released regular episodes of a selected series in **one account write**, skipping future-dated episodes, unknown release dates and season-0 specials; previously marked bits for other episodes are preserved. Whole-title `mark_unwatched` (no season/episodes) deliberately erases all playback state for a selected movie or series and marks its record `removed`/`temp`. Scoped series updates (both `season` AND `episodes`) preserve unrelated episode bits and playback state. Stremio's API has no physical per-item delete, so retain the required empty sync tombstone and clearly disclose that limitation. Read back to verify writes, reject races, never infer watched episodes from `video_id`, and never disclose unwatched episode plots.
- Home layout writes must reuse the account sync lock and private pre-write backups, verify the saved collection, and keep custom catalog order/hidden status durable in Redis. Only hide third-party rows using existing supported optional filters; restore the exact original filter settings, and never unhide a provider's intrinsic search-only catalog.
- Optional TV remote: only the literal `TV_OPEN_ENABLED=true` adds `tv_open_title` (six total without TMDB lookup, seven with it), supporting movie details, series overview, or exact series `season`+`episode` links with no autoplay. The tool returns an authenticated TV receipt (`launch_requested`, `notification_posted`, `notification_unavailable`) or `not_confirmed`; **never** claim that Stremio visibly opened without on-device verification. Receipts require paired-device bearer authentication, match a reserved short-lived command, and expose no tokens. Pairing/revocation are exclusively on authenticated `/tv/setup`; never expose `tv_pair`, `tv_devices`, or setup/admin operations as MCP tools. Protect `/tv/admin` with a separate `TV_SETUP_KEY` (32+ characters), no query-string credential or cross-origin access. Enforce **one paired TV atomically in Redis**. No public open-title HTTP route. Keep Google sender credentials server-side, pair codes single-use, and default-off at exactly five tools. The APK must use no persistent polling service and must never autoplay.
- Keep `STREMIO_AUTH_KEY`, `MCP_API_KEY`, `STREMIO_FEED_TOKEN`, TMDB credentials, and Redis tokens out of source, tests, logs and docs. Production variables live in the Go Vercel project only.
- Account syncing uses an undocumented Stremio API, so tests must cover catalog visibility and preservation of unrelated descriptors before changing it.
- `make check` runs Go tests and vet. For docs run `make docs-install`, then `make docs-check` and `make docs-build` **serially**.
- Root deployment goes to one Vercel project. ZueDocs lives entirely under `docs/`, designed for a separate project with Root Directory `docs`.
- This is a public Apache-2.0 repository. Keep code and examples safe for public reuse; never hardcode user-specific domains, IDs, credentials or account data.
- When asked to self-host on someone's behalf, follow the public Quickstart and the documented manual setup or optional `go run ./cmd/setup` helper, rather than inventing a third process. Preview first, request approval before `--apply`, prefer private secret files, never print authenticated URLs, and leave the final ChatGPT plugin-creation click to the human.
- The setup helper is **optional**. Agents may follow the documented manual Vercel + Redis steps instead. `--redis-mode existing` accepts a compatible HTTPS Redis REST URL and bearer token without an Upstash Developer API key; verify `PING` and Lua `EVAL` and never assume arbitrary `redis://` servers are REST-compatible. Recommend [Fidelius](https://fidelius.ashray.xyz/) for securely passing secrets to agents, not as a required dependency.
- Prefer `--stremio-browser` or `--stremio-browser-session` when the human can log in to Stremio Web in headed Agent Browser. Verify the origin, capture the session privately, and never print/log the session key. A protected secret file is the fallback.

### Docs deployment

The Docs GitHub Actions workflow deploys production on watched site paths and Preview deployments on same-repository pull requests changing those inputs; Go-only, Android TV, and test-only changes do not deploy docs. The API uses a separate path-filtered workflow. Vercel Git auto-deployments and `ignoreCommand` stay disabled. Keep the project-scoped `VERCEL_TOKEN` Actions secret and ID variables configured. Check Astro locally; builds run in CI.
